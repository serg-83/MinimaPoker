# MinimaPoker — Руководство по игре

## Обзор

MinimaPoker — децентрализованная P2P-игра в Texas Hold'em, работающая как MiniDAPP на блокчейне Minima. Центрального сервера нет — вся игровая логика выполняется напрямую между игроками через P2P-слой Maxima. Средства защищены офф-чейн платёжными каналами (протокол eltoo), поэтому реальные токены Minima находятся в игре без необходимости доверять третьей стороне.

---

## Основные принципы

### Децентрализация
- Нет сервера, нет казино. Каждый игрок запускает игру на своём узле Minima.
- Все сообщения передаются P2P через Maxima с именем приложения `MinimaPoker`.
- Блокчейн задействуется только при открытии и закрытии платёжного канала.

### Честная раздача карт (Commit-Reveal)
Карты раздаются с помощью криптографической схемы commit-reveal:

1. **Фаза commit** — каждый игрок генерирует случайный 64-символьный hex-секрет, хэширует его (SHA3) и отправляет хэш всем остальным.
2. **Фаза reveal** — каждый игрок раскрывает секрет. Игра проверяет совпадение с хэшем.
3. **Объединение сидов** — все секреты объединяются через XOR в единый сид.
4. **Перемешивание** — колода из 52 карт детерминированно перемешивается на основе сида. Результат одинаков у всех.

Позиция дилера также определяется из сида: `parseInt(seed.substring(0,8), 16) % players.length`.

### Платёжные каналы (Eltoo)
- Канал использует механизм **eltoo** (N-of-N мультиподпись), аналогичный проекту Thunder.
- Каждое действие, изменяющее балансы, создаёт новое офф-чейн обновление состояния, подписанное всеми.
- Если игрок пропадает, любой участник может инициировать **диспут** — опубликовать триггер-транзакцию и дождаться таймаута расчёта.

### Enforcer (детерминированный координатор)
Роль хоста отсутствует. Вместо этого **enforcer** — игрок с наименьшим pubKey среди участников — автоматически запускает игру при открытии канала. Это детерминировано и не требует доверия.

## Ход игры

### 1. Лобби
- Игроки видят столы друг друга через контакты Maxima.
- **Create Table** — задать максимальное количество игроков (2–4), блайнды (например, `10/20`) и buy-in (минимум 20 BB, по умолчанию 100 BB).
- **Join Table** — перейти к существующему столу.

### 2. Создание канала
Любой игрок нажимает **Create Channel**:
- Отправляется `REQUEST_NEW_CHANNEL` всем участникам.
- Каждый принимает → подписывает триггер и расчётную транзакцию → отвечает `REQUEST_ACCEPTED`.
- Инициатор собирает все ответы, подписывает транзакцию финансирования, публикует в блокчейне.
- Статус канала становится **OPEN** → enforcer автоматически запускает первую раздачу.

### 3. Фаза Commit
- Каждый игрок генерирует секрет и отправляет `COMMIT` с SHA3-хэшем.
- Когда все коммиты получены → переход в фазу reveal.

### 4. Фаза Reveal
- Каждый игрок отправляет `REVEAL` с оригинальным секретом.
- Если секрет не совпадает с хэшем → фаза commit перезапускается.
- Когда все секреты верны → колода перемешивается → раздаются карманные карты.

### 5. Раунды торговли
Стандартная структура Texas Hold'em:

| Раунд    | Общие карты | Ход начинает                    |
|----------|-------------|---------------------------------|
| Pre-flop | нет         | игрок после большого блайнда    |
| Flop     | 3 карты     | первый активный после дилера    |
| Turn     | 1 карта     | первый активный после дилера    |
| River    | 1 карта     | первый активный после дилера    |
| Showdown | —           | лучшая рука забирает банк       |

Доступные действия: **Fold**, **Check**, **Call**, **Raise**.

После каждой ставки, изменяющей балансы, отправляется `SEND_FUNDS` с новыми подписанными транзакциями. Все игроки контрподписывают и отвечают `REPLY_SEND_FUNDS`.

### 6. Таймауты
- **Ход игрока** — 30 секунд. По истечении enforcer принудительно выполняет fold/check.
- **Фаза commit/reveal** — 20 секунд. По истечении enforcer подставляет нулевой секрет.
- **Диспут** — запускается автоматически при обнаружении неактивности. Таймаут канала: **30 блоков** (~25 мин).

### 7. Закрытие канала

**Кооперативное** — финальная транзакция подписывается всеми и публикуется. Средства распределяются немедленно.

**Диспут (одностороннее)**:
- Триггер-транзакция публикуется в блокчейне.
- После `MIN_UPDATE_COINAGE = 5 блоков` публикуется последняя update-транзакция.
- После `MIN_SETTLE_COINAGE = 30 блоков` публикуется расчётная транзакция и средства распределяются.

## Справочник сообщений Maxima

Все сообщения — JSON-объекты, отправляемые через `maxima.sendWithAck()` с `application: MinimaPoker`.

| Сообщение               | Отправитель    | Когда                                           | Что делает                                                      |
|-------------------------|----------------|-------------------------------------------------|-----------------------------------------------------------------|
| `TABLE_CREATE`          | Создатель      | После создания стола                            | Вставляет стол в БД всех контактов                              |
| `TABLE_DELETE`          | Создатель      | После удаления стола                            | Удаляет стол из БД всех контактов                               |
| `TABLE_JOIN`            | Входящий игрок | При входе за стол                               | Добавляет игрока в список игроков стола                         |
| `TABLE_LEAVE`           | Игрок          | При выходе из стола                             | Удаляет игрока из списка игроков стола                          |
| `REQUEST_NEW_CHANNEL`   | Инициатор      | После нажатия Create Channel                    | Просит других игроков принять создание канала                   |
| `REQUEST_ACCEPTED`      | Каждый игрок   | После принятия запроса                          | Отправляет подписанные триггер + расчётную транзакции           |
| `REQUEST_DENIED`        | Каждый игрок   | После отклонения запроса                        | Уведомляет инициатора об отказе                                 |
| `CREATE_CHANNEL`        | Инициатор      | После сбора всех принятий                       | Отправляет финансирование + подписанные транзакции всем         |
| `FINISH_START_CHANNEL`  | Каждый игрок   | После получения CREATE_CHANNEL                  | Подписывает funding tx; инициатор публикует; канал → OPEN       |
| `GAME_START`            | Enforcer       | Автоматически при OPEN                          | Инициализирует состояние игры; запускает фазу commit            |
| `COMMIT`                | Каждый игрок   | В фазе commit                                   | Отправляет SHA3-хэш секрета всем                                |
| `REVEAL`                | Каждый игрок   | В фазе reveal                                   | Отправляет оригинальный секрет для проверки                     |
| `BET`                   | Активный игрок | При fold / check / call / raise                 | Отправляет действие всем; запускает обновление канала           |
| `SEND_FUNDS`            | Обновляющий    | После каждой ставки, изменяющей балансы         | Отправляет новые подписанные расчётную + update-транзакции      |
| `REPLY_SEND_FUNDS`      | Каждый игрок   | После получения SEND_FUNDS                      | Контрподписывает транзакции; состояние применяется              |
| `SPEND_CHANNEL`         | Любой игрок    | При кооперативном закрытии                      | Финальная транзакция для подписи всеми; публикуется             |
| `CHANNEL_CLOSE`         | Любой игрок    | После закрытия канала                           | Уведомляет всех обновить статус на CLOSED                       |
| `DISPUTE`               | Любой игрок    | При одностороннем закрытии / таймауте           | Публикует триггер-транзакцию; запускает таймер диспута          |
| `LOBBY_CHAT`            | Любой игрок    | При отправке сообщения в чате                   | Рассылает текстовое сообщение всем контактам                    |

## Схема базы данных

| Таблица    | Назначение                                                                    |
|------------|-------------------------------------------------------------------------------|
| `tables`   | Активные столы (id, создатель, блайнды, buy-in, макс. игроков, статус)        |
| `players`  | Игроки за каждым столом                                                       |
| `channels` | Состояние канала (транзакции, балансы, статус, sequence, disputeStartBlock)   |

## Безопасность

- Секреты генерируются локально через `utils.genRandomHexString(64)` — 256 бит энтропии.
- Хэши коммитов используют SHA3 через команду Minima `hash data:`.
- Все транзакции канала требуют N-of-N подписей.
- Механизм eltoo гарантирует, что последнее состояние всегда побеждает в блокчейне.
- Данные Maxima кодируются в UTF-8 hex (`encodeURIComponent` / `decodeURIComponent`).
